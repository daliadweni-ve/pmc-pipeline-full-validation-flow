PMC release test, as a pipeline

Before a new PMC version is released, a robot tests it with 3 users working on the same project at the same time, like 3 real colleagues. This page shows what each user does, when they wait for each other, and how long they wait.

5 ideas you need to read the picture

1. Three users

Each user is its own browser, clicking through PMC by itself. They all work at the same time.

1the lead 2helper 3checker

In the code: primary, secondary1, secondary2.

2. Line-ups

A line-up is a point where everyone must finish before anyone continues. There are only a few line-ups, at the start of each round.

Line-up

3. Gates

A gate is a “done” flag between specific users. One user raises it when they finish something. Another user waits at it until it is raised.

raises Gate 7 → waits for 1 · Gate 7
  • The waiting user checks the flag every 1 second.
  • It gives up after 10 minutes.
  • The flag is raised even if that user’s step failed, so nobody waits forever.

4. Live pop-ups

When a user saves Goods Receipt or Timesheet Review, PMC shows an “Updated” pop-up to other users. This pop-up only reaches users who are already on that screen. That’s why checkers open the screen early and sit there waiting.

5. Three kinds of time

  • Pause: always waits this long so the screen can load (0.2 to 3 seconds).
  • Time limit: waits up to this long but continues as soon as ready.
  • Retry: tries again every few seconds until it works or the limit is reached.
up to 90 sreloads every 5 s
